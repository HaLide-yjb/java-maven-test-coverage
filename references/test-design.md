## 第 1 章：测试输入、预言与环境

对应 §1.1.1—§1.1.3；§1.2、§1.3 是白盒程序和黑盒系统的应用背景。

测试用例由“数据、预言、环境”构成。每个测试至少明确：要验证哪个规则或当前行为、输入为何能到达该规则、预期结果由何而来。报告补充实际输出和原因描述。调用后没有有效断言，不能据此说明有检错能力。

预言优先来自明确需求和接口契约，也可采用结构不同的独立查表、手算或有界参考算法。不得调用被测算法生成它自己的预期。复用输入构造可以减少重复，复用同一错误计算作为预言会掩盖缺陷。

§1.1.3 的 S（规格）、P（实现）、T（测试）分析要求区分：

- 已实现且应当测试的需求；
- 规格要求但实现缺失的行为；
- 实现存在但规格未明确的行为；
- 尚未进入测试集的行为。

实现与注释或规格冲突时记录冲突及依据。为研究覆盖率而断言“当前实现行为”，须明确标识，不能因此宣称需求已满足；也不能擅自修复只读生产代码。覆盖率 100% 与业务正确性不是同一结论。

把课程示例转为本项目的设计思路：

| 课程背景 | 可迁移的方法 | 应用时核对 |
| --- | --- | --- |
| Triangle（§1.2.1） | 区间、变量间关系、分类条件 | 只满足单个输入范围，未必满足多个变量间约束 |
| NextDay（§1.2.2） | 年月日依赖、月末／年末、闰年和无效日期 | 使用项目实际日期表示及规则，不能把教材规则直接强加给卡片有效期 |
| MeanVar（§1.2.3） | 空／单元素／多元素、循环边界、数值误差 | 明确空输入契约、整数溢出或浮点精度，不把数学实数结论直接套入 Java |
| 超市、办公软件、智能应用（§1.3） | 状态、操作序列、环境和间接预言 | 仅在实际目标包含这些交互时采用；不因此扩大为 GUI、硬件或外部系统操作 |

日期测试使用被测类实际的时间基准，考虑连续两次读取跨月／跨年；不要把今天写死后分享给别人。环境、共享状态和 mock 生命周期必须可控。

<a id="course-2"></a>
## 第 2 章：PIE 与 Bug 特性

### §2.1.1—§2.1.2：从 Fault 到 Failure

按实际执行顺序检查三个条件：

1. Execution：输入是否运行到目标语句或变异位置？
2. Infection：执行到该位置后，原程序和变异体的中间状态是否真的不同？
3. Propagation：差异是否传播到返回值、异常、约定可见状态或有效的交互断言？

行覆盖只提供第一层证据。执行了 `x + 0` 与 `x - 0` 未产生差异；中间和变成负数，也可能经过后续运算被完全屏蔽。对每个存活变异分别写 E/I/P，找缺少的条件，再设计输入或断言。

例：Luhn 的求和变异可能满足 E、I，但若最后只判断是否整除 10，整体取负的差异不能传播为布尔结果差异。该结论必须针对具体实现证明，不能扩展成“所有求和变异都等价”。

### §2.2.1—§2.2.4：反向定义、不确定性、非单调性与干涉

- 一个失败用例被某次改动修好，并不足以证明修复位置或修复方式正确。增加来自其他分区、路径和独立预言的证据；默认范围内不修改生产代码。
- 同一个失败可能有多种原因；先排除测试预期、环境、时间、数据和依赖问题，再定位实现。
- 通过数和覆盖率的升降不能单独评价改动是否正确。完成针对性验证后仍需全量回归。
- 多个错误可能相互抵消或共同触发，重复计算也可能补偿单个变异的效果。分别推导具体条件，不把“某几项一起改变会失败”当作一阶 PIT 变异已被检出。
- mock 只隔离明确的依赖边界，并在用例结束时释放；被测算法本身需有真实对象测试。不能 mock 被测方法的返回值制造覆盖。

<a id="course-3"></a>
## 第 3 章：多样性测试

### §3.1.1：简单随机测试

在定义清楚的输入域中抽样，记录种子、样本数、输入规模及预言；失败输入保留为可重复的回归用例。有效、无效、极短、边界等类别按需分别生成，避免绝大部分样本在同一前置检查处失败。

对卡号可以先确定长度、前缀和字符类别，再生成剩余位。随机总预算、最大长度和进程期限均有限；禁止“不断生成直到覆盖／杀死”的循环。均匀抽样不代表输入域、执行域、输出域都均匀。有限样本通过不证明全域正确或变异等价。

### §3.1.2：自适应随机测试（ART）

当随机样本集中、怀疑块状或带状故障区域时，可在既定预算内扩大分布。FSCS 的可执行形式：

1. 维护已执行而未发现失败的样本集 E。
2. 每轮只生成固定数量候选 C。
3. 对候选 c 计算其到 E 的最小距离，选择该最小距离最大的候选执行。
4. 到达样本数或时间上限即停止；发现失败则保留输入并分析。

数值因素先按范围归一化；字符串需定义有意义的特征／距离，例如长度、前缀类别、字符类型。不能不加说明地把数字差距当成卡号语义距离，也不能无限扩大候选集。ART 是补充分布的方法，不能证明矛盾路径可行。

### §3.1.3：引导性随机／符号执行与动态符号执行

适用于已知目标分支但纯随机难命中：

1. 选一条短的候选路径，将输入符号化。
2. 按真实执行顺序收集条件，得到路径约束 Φ。
3. 否定希望翻转的分支条件，同时保留到达此前位置的约束。
4. 手工推导或使用可用求解工具得到候选输入，再用原程序具体执行核对。
5. 动态符号执行可以从一次具体执行开始逐步探索邻近路径；限制路径数、深度、循环展开及单次求解时间。

约束必须包含解析、类型、数组长度、短路、异常及变量依赖；Java int 要考虑 32 位回绕，字符串／浮点不能假装成无限精度整数。仅在准确模型下的矛盾推导或 UNSAT 才支持该路径不可行；一个模型的 UNSAT 也不自动覆盖所有入口路径。SAT 候选要实际验证；求解超时、UNKNOWN、工具缺失均保留未验证状态。

手工列约束属于静态推导，不能写成“已经运行符号执行／SMT 工具”。不因教材提到工具便自行安装、改构建或更改生产实现。

### §3.2.1：等价类划分

按输入、输出和执行行为分别考虑分区。有效与无效分区都要覆盖；每个维度的分区应尽量互斥、完整，行为不同则细分。代表用例只是工程抽样依据，不是同一分区所有输入等价的形式证明。

卡号项目可按以下维度建表，具体规则以该类源码／契约为准：

- 长度：null、空、太短、最小合法、中间、最大合法、太长；
- IIN：离散前缀、连续范围、范围之间空隙、不同位数、足够／不足解析位数；
- 字符：数字、前导零、空白、符号、字母及实际解析行为；
- 校验和：正确、改动校验位、影响不同加倍位置的数字；
- 日期／CVV：独立的格式、长度、内容、跨年／跨月及异常分区。

四种组合强度要区分：

| 类型 | 设计动作 |
| --- | --- |
| 弱一般 | 有效分区分别至少取代表，不要求所有笛卡尔积 |
| 弱健壮 | 在上项上逐次引入一个无效因素，其他因素保持有效 |
| 强一般 | 在可行约束下组合各因素的有效分区 |
| 强健壮 | 在可行约束下考虑有效与无效分区的组合；控制组合规模 |

先用单个无效因素避免错误被前置校验掩盖，再用多因素组合查交互。“无效”指不满足业务规则，仍可能是应当执行并断言拒绝或异常的测试；不要把它与无法形成的路径状态混为一谈。需要前缀解析时输入应有足够位数；不能把过短导致的异常误当作 IIN 判断已覆盖。区间并集的重叠必须计入预期，例如某个端点越过一个范围后仍可能命中另一个前缀规则。

### §3.2.2：划分随机测试

先建分区，再向每个分区分配有限样本，避免罕见但重要类别在全域随机中被遗漏。至少给关键边界／异常子域分配预算，再按风险、大小或历史故障调整。

课程的 P、E、F 度量分别关注检出概率、检出数量期望和首次检出所需测试数；比较策略时控制预算和环境。优化抽样效率不能代替本任务的覆盖率与 PIT 原始计数，也不能用概率推论证明等价。

### §3.3.1—§3.3.2：组合准则与生成

列出因素、每个因素的离散取值和约束，再选择 t-wise；覆盖数组 CA 适合等取值数，混合覆盖数组 MCA 处理不同取值数，必要时对高风险因素使用更高强度。t-wise 覆盖保证相应可行取值组合被选到，不保证所有路径、所有逻辑故障或所有变异被检出。

可使用现有小表、贪心逐步覆盖未覆盖组合、扩展已有测试集，或在已具备工具时使用课程举例的组合生成工具。生成后核对约束、未覆盖组合、预言和实际目标路径；不能只有组合数据而没有断言。

对简单 `A && B`，先检查四种组合：

| A | B | 结果 | Java 短路与测试用途 |
| --- | --- | --- | --- |
| T | T | T | 两个条件均执行；成功路径 |
| T | F | F | B 的失败路径可被观察 |
| F | T | F | A 失败，B 在此表达式中不执行；保持业务 B 有效便于隔离 A |
| F | F | F | 多个无效因素并存；不能据此说明两个子条件都执行 |

两个因素很小时可以完整枚举；较多因素采用约束下组合。长度是否有效与前缀是否有效可作为因素，校验和、日期等另加因素；以源码实际调用顺序核实哪些值被掩盖。

<a id="course-4"></a>
## 第 4 章：故障假设测试

### §4.1.1—§4.1.2：黑盒与白盒边界

黑盒从规则分区边界选值。离散区间 [min,max] 通常检查 min−1、min、min+1、max−1、max、max+1；对长度、首尾位置、空／满、日期切换分别设预期。浮点相邻值按精度／表示讨论，不机械加减 1。

白盒从比较符号、逻辑子条件、循环控制及数组访问选边界。除输入边界外，还考虑计算后的阈值、短路以及非判定语句的数值边界。

循环优先检查零次、一次、两次及有界的首／末命中、正常退出、break、异常退出；先确认这些路径在原程序中存在。若原程序必执行一次并总以 break 退出，就不能为了凑“零／多次循环覆盖”无界尝试。变异可能改变终止性，测试超时加外层进程期限，并依入口 Skill 的流程移除／替换危险写法。

<a id="mutation"></a>
### §4.2.1：变异分析、等价与强弱杀死

先定位报告里的类、方法、行、变异算子及具体变更，再检查原代码，必要时只读核对字节码。PIT 对字节码操作，不能只根据一个算子名称猜测源码含义。

| 报告现象 | 下一步 |
| --- | --- |
| NO_COVERAGE | 检查发现测试、执行路径、异常前置条件、统计范围和新鲜度 |
| SURVIVED | 分别推导 E/I/P，设计可区分的输入与有效断言 |
| KILLED | 核对实际失败断言／异常与目标变异关系 |
| TIMED_OUT | 先按终止性风险处理，不能伪称普通断言检出 |
| 运行／环境错误 | 保留错误状态，不能改写成检出或等价 |

课程区分两种“相同”：给定有限测试集 T 没有杀死变异，只说明相对该 T 未区分；对所有允许输入均无可观察差异，才支持语义等价。几次测试一致、随机搜索失败或一轮 PIT 存活都不构成后一种证明。

弱杀死观察执行后中间状态差异；强杀死还要求差异传播为可观察输出。对本任务的 PIT，不能因局部变量被感染就宣称已检出；正常结果、异常和真实可见状态应由断言观察。反射也不能正常读取已经消失的局部栈变量；篡改被测算法、mock 被测结果或改写报告不能代替原目标。

分析每个一阶变异时，其余代码保持原样。等价证明至少覆盖：所有相关输入分区、异常、数值溢出／舍入、状态变化及所采用的可观察语义。若存在区分输入，优先形成有界回归；证据不足则标记“尚未解决”。

### §4.2.2：变异测试优化

课程讨论选择变异、抽样、聚类以及执行优化，目的是减少评估成本。本任务已有完整统计范围和 100% 目标，不能据此删减算子、排除类、移除难检出变异或把弱变异数替换成 PIT 结果。

可先跑变更分区的普通测试，修复输入与断言后再做完整验证，避免每次小改都重复全量昂贵操作。最终仍需用户指定的 Maven test 与完整 PIT。任何子集实验须标注其范围，不能替代全项目结果；已证明等价也保留在原始分母中。

### §4.3.1—§4.3.2：逻辑故障与布尔差分

把复杂判定拆成不含逻辑连接符的条件，识别否定、AND、OR、括号、短路与重复条件。DNF／CNF 可帮助分析，实际 Java 表达式可能有副作用或异常，不能仅凭布尔代数重新排序执行。

课程的十类故障可指导输入设计：

| 类型 | 关注的变更 |
| --- | --- |
| ORF | AND／OR 互换 |
| ENF | 整个子表达式取反 |
| VNF | 单个条件取反 |
| ASF | 括号／结合关系改变 |
| MVF | 条件缺失 |
| VRF | 用其他条件替换目标条件 |
| CCF | 条件 c 被 c AND c′ 替换 |
| CDF | 条件 c 被 c OR c′ 替换 |
| SA0、SA1 | 条件固定为假或真 |

针对具体原表达式 P 与变异 P′，区分条件是 `P XOR P′ = true`。独立影响可由 `P(c=true) XOR P(c=false)` 推导，但必须同时满足到达该位置的路径约束及输入间关系。

例：P=A AND B，要观察 A 的作用固定 B=true；观察 B 的作用固定 A=true。若已有约束强制 B=false，则 B 会屏蔽 A，应换可行路径；若所有到达路径都强制 B=false，就需要不可行／冗余证明。

故障蕴涵关系可在满足前提的模型中帮助优先选用例，不可直接推论“若干逻辑故障检出便等于整个项目 PIT 100%”。小表达式优先手算可行真值表，避免不必要的指数展开。

<a id="course-5"></a>
## 第 5 章：图分析测试

### §5.1.1—§5.1.2：可达性与控制流图（CFG）

按基本块表示顺序、分支、循环、return、throw、break、continue，标注实际入口及退出，必要时下钻到编译指令。沿图画得出的路线是语法候选路径；存在真实输入使其执行才是语义可行路径。

对红色行／分支先列到达条件和变量状态，不能把“图上有边”直接等同于“测试一定可以走到”。源码大括号或编译器回跳计入行号时，用只读字节码及 LineNumberTable 核对其含义。

### §5.1.3、§5.3.1：数据流图、定义—使用与约束

沿变量的定义（def）、计算使用（c-use）、谓词使用（p-use）追踪；定义清晰路径中间没有重新定义。对关键变量按需要检查 all-defs、all-uses 和有界的 def-use 路径，并覆盖可行的谓词真／假使用。

具体操作：

1. 列出目标变量的初值及所有赋值位置。
2. 找到目标使用位置和可到达的定义，检查中间是否重写。
3. 把到达条件与取值不变量结合，构造输入或推出矛盾。
4. 对实测路径和静态排除的路径分别记录证据。

CFG 解释“如何走”，DFG 解释“值从哪里来”，可合并分析。对循环可按有限迭代展开、给赋值编号辅助推理；不要仅因采用单赋值表示便假定实际循环依赖消失，也不改写只读生产源码。

例：IIN 在进入两次扫描前仅解析一次并保存在局部 int，中间未重新赋值，则两次扫描看到同一个数。重复调用构造器或改动外部输入，不能在同一次扫描中把这个已解析的局部值换掉。

### §5.1.4：事件流图（EFG）

当实际目标具有事件或状态序列时，定义事件、初始状态、可跟随事件、受限焦点／前置状态，构造有限的合法序列，检查每次转移后的可见状态。对没有 GUI 的 Maven 算法项目，不强行引入界面自动化；构造、setter、校验等接口有状态依赖时可借鉴这一思路。

### §5.2.1：L-路径测试

以 L=0 的节点、L=1 的边、L=2 的边对逐级分析，再按缺口选择较长片段。对本任务，节点／行覆盖、边／分支覆盖和变异检出应分别核验；覆盖一个指标不意味着其他指标自动满足。

路径片段需能扩展为从真实入口到退出的可行执行。增大 L 可能带来路径爆炸，不能通过无界枚举寻求全循环路径覆盖。

### §5.2.2：主路径测试

主路径是不能被其他简单路径真包含的极大简单路径，允许以起点为终点的简单闭环。可对小型 CFG 枚举有长度上限的简单路径、剔除真子路径，再将主路径扩展为入口到出口的测试路径。

对循环选择有限的进入、一次回边、退出及必要的少量重复；检查扩展路径是否语义可行。有限个主路径并不保证枚举成本小，也不保证每条都可执行。发现矛盾要记录约束，不能让测试永久走环。

### §5.2.3：基本路径测试

构建 CFG，在连通、单入口／统一出口等模型前提下用 `V(G)=E−N+2` 辅助估计独立路径数；选择可行且线性独立的路径，逐条生成输入。break、异常出口和编译器展开会影响建模，需核对实际 CFG。

独立路径覆盖不等于枚举全部执行路径，也不自动保证所有逻辑故障检出。圈复杂度给出结构信息，不能使语义不可行的路径变为可行；不要仅凭一个复杂度数字声称测试已经充分。

### §5.3.2：逻辑覆盖与 MC/DC

分别核对判定真／假、子条件真／假、组合以及独立影响。条件覆盖与判定覆盖不能简单互相替代；完整组合会有指数成本，MC/DC 的用例数也不能对所有表达式无条件套用 n+1。

为目标条件选择一对可行输入，使该条件改变，其他相关条件保持要求的值，并使整体判定改变。保留用例对、条件向量和预期结果；记录 Java 短路可能导致部分子条件未被执行。

若条件依赖同一个变量，如 `x>=min && x<=max`，某些布尔向量本来不可行；不能给各条件任意赋真／假来替代输入。需要时用 §3.1.3 的约束检查和 §5.3.1 的数据依赖说明原因。

## 判定障碍前的缺口复核

本流程既用于剩余覆盖缺口，也用于存活变异；结论回写原有说明文档。

1. **固定对象**：源码指纹、类、方法、行、实际变异及报告版本。不能用旧报告的行号证明新源码。
2. **固定预言和语义**：说明要观察返回、异常、状态还是明确的依赖交互；不要遗漏异常路径。
3. **输入分区／边界**：回查 §3.2.1、§4.1；列代表值、边界及异常输入，区分已有用例与待补用例。
4. **组合／逻辑**：回查 §3.3、§4.3、§5.3.2；寻找避免掩蔽的可行条件组合和独立影响对。
5. **路径／数据**：回查 §5.1、§5.2、§5.3.1；写出入口到目标的条件和变量不变量。用 §3.1.3 手工推导或已有工具求候选输入。
6. **E/I/P**：对变异用 §2.1.2、§4.2.1 区分“到达不了”“未感染”“感染未传播”。有区分输入便写有界测试；暂时找不到便继续分析适用方法。
7. **有限补充搜索**：当仍存在可行但难命中的输入，选 §3.1 或 §3.2.2 补充探索。记录预算与结果；已经严格矛盾的路径不需要再随机搜索。
8. **按证据收束**：给出输入反例、不可满足约束或完整等价推导；证据不足标“尚未解决”，列下一步。只把当前证明覆盖的对象列为障碍。

每项至少记录“课程节号 → 拟解决的条件 → 实际动作／输入或公式 → 结果 → 后续”。共同证明可合并，但每个受影响变异须有独立编号与定位。无需为了填满表格运行不适用工具。

四类常见推导形式：

| 类型 | 需要证明的内容 |
| --- | --- |
| 局部状态不变量 | 到达目标前变量只能为某值，与目标分支条件冲突 |
| 重复扫描 | 进入第二次扫描意味着不满足 R(x)，第二次成功又要求 R(x)，且 x 和范围不变 |
| 异常支配返回 | false 必在返回前抛异常，返回位置只能观察 true |
| 数值差异被屏蔽 | 原值与变异值经后续判定总得相同结果，且异常、溢出、状态均未产生可观察区别 |

这些只是证明思路，必须用当前源码验证其前提。若存在其他定义、异常恢复、可变依赖或公开中间状态，原结论可能失效。

## 证据等级与停止条件

| 证据 | 可以写什么 | 不能推出什么 |
| --- | --- | --- |
| 已运行输入及有效断言失败 | 该具体反例区分原程序与相应变异 | 所有其他变异都已解决 |
| 有限用例／随机样本均通过 | 在这些输入和环境中未观察到差异 | 全输入等价、不可达或程序全正确 |
| 手工数据流／路径矛盾 | 在明确入口与 Java 语义前提下该路径不可行 | 未分析的其他路径也不可行 |
| 完整可观察行为等价推导 | 指定变异在约定语义下等价 | 所有 SURVIVED 都等价 |
| 求解超时、UNKNOWN、工具未运行 | 尚未验证，列替代方案和下一步 | 不可满足、无法处理或目标达成 |

在相同源码与配置下已有充分证明时，停止无效重复搜索；普通未检出项继续改进。原始 100% 目标不因证明等价或不可达而被改写。不能扣减原始分母、排除难测代码或以舍入百分比宣称达成。

课程中的抽象公式、经验结论和示例计数需要按实际模型核算；不把代表性抽样、路径基、逻辑故障层次关系当作对任意 Java 程序的绝对保证。对推导前提有疑问时记录局限，优先使用当前源码的具体约束与可复现实验。
