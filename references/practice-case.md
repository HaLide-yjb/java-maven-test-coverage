# Credit-Card-Validator 练习中的已验证经验

本页是共享的定位参考，不是可直接套用的评分结果。读取实际项目的源码、编译版本和最新报告后再作结论。详细证据始终维护在项目原有的“测试覆盖率阻碍说明.md”，本页不能代替它。

先读[课程方法与缺口复核](test-design.md#review-gaps)。本例涉及 §2.1.2 PIE、§3.1.3 路径约束、§3.2.1 等价类、§4.1 边界、§4.2.1 强弱变异、§4.3 逻辑，以及 §5.1／§5.3.1 控制流与数据流。以下结论来自具体源码推导，不能由“未覆盖／存活”直接推出；方法复核时分别记录已有动态测试、手工静态推导和尚未运行工具。

| 目标 | 当时的源码位置 | 已验证现象 |
| --- | --- | --- |
| TypeChecker.checkType | while 第 20 行；兜底 if 第 56 行；循环尾第 61 行 | type 初始 null，所有赋值后立即 break；两个自然 false 分支和尾部回跳不可达 |
| VerveValidator.checkIINRanges | 第一轮第 53 行，第二轮第 61 行，成功语句第 63/64 行 | 两轮重复相同区间，第二轮成功路径不可达，并产生 7 个等价变异 |
| LuhnValidator.algorithmCheck | 求和第 76 行、整除判断第 79 行 | 累加改累减仅整体取负；是否能被 10 整除不变。Java int 回绕及 MIN_VALUE 也不改变结论 |
| Validator.validate | 异常第 61 行，返回第 64 行 | false 在 return 前抛异常，返回处替换为 true 等价 |

曾出现 TypeChecker 兜底判断被变异为 false 后无限重复扫描。危险的直接 OTHER 用例被移除，替换为：隔离卡种路由，限制每种依赖仅构造一次，重复构造立即失败；具体卡种算法另用真实对象测试。仅加线程超时并不能确保停掉不响应中断的循环，所以外部还加了有界的进程树终止。

当时完整回归为 109 个用例通过；生产类/方法 100%，行 494/497、分支 233/236；PIT 488/491 行，263/272 变异、9 存活、0 超时。它们是 2026-10-18 的历史结果，**不是所有项目的目标上限，也不是新运行的结果**。

Windows 上曾因中文绝对路径的编码转换使 JaCoCo 把执行数据写到预期目录之外。仅调整已配置代理的运行参数为 ASCII 相对输出路径后正常；没有修改 pom.xml、移动项目或修改系统编码。不得把此修复无条件套用到所有工程。
